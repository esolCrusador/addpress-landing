    Web

    Give visitors a shareable page for your Web Chat bot and its public widgets.

    Visitor-facing portal page for an Add Process Web Chat bot: shows the bot profile and links to open any public widgets attached to that bot.

    Application navigation

    PageURL
    Public bot pagehttps://app.addprocess.pro/addprocess/web-chat/bots/public/{username} — replace {username} with the Web Chat bot username from Create bot

    In the app: Configuration → Create bot → open the Web Chat bot’s username link (channel public URL). That link targets the path above.

    Do not use the deprecated admin list at /addprocess/web-chat/bots as a customer workflow—it is hidden from the side nav and kept only for legacy access.

    What it does

    • Resolve a Web Chat bot by username.
    • Show bot name, @username, and description when available.
    • List available widgets that are public for that bot, each with a direct chat link on the widget domain (…/widget?widgetId=…).
    • Show a not-found state if the username does not match a bot, or an empty state if the bot has no public widgets.

    Who uses it

    Builders who want a shareable landing URL for Web Chat (campaigns, QR codes, bio links) alongside or instead of site embed.

    UI guide

    Public page (visitor)

    • Header card: Web Chat icon, bot name, @username, optional description
    • Section Available widgets: cards with widget name, “open chat” affordance, copyable/openable widget URL
    • Empty: message that the bot has no public chats
    • Unknown username: bot-not-found title and description

    How a widget becomes listed

    Widgets are configured under Widgets. A widget appears on the bot's public page when all of the following hold:

    • the widget is enabled,
    • Standalone public is checked on the widget, and
    • the bot is attached to the widget with the Assign action (a Notify-only row does not list the widget).

    Notes

    • Widget chat still runs on the configured widget domain; the portal public page mainly discovers and links those chats.
    • Conversation behaviour still comes from Bot assignments on the Web Chat bot.

    Public Web Chat bot page

    Give visitors a standalone portal URL for a Web Chat bot that lists its public widgets and opens chat on the widget domain.

    What the customer can accomplish

    Share one link (/addprocess/web-chat/bots/public/{username}) that presents the bot and lets people open chat without embedding a script on a site first.

    Why it is useful

    Useful for social bios, QR codes, email campaigns, and testing when a full site embed is not ready—complements Embed Web Chat on a site.

    Prerequisites

    • A Web Chat channel bot with a username (Connect a channel bot)
    • Bot activated with the behaviour you want (Activate a bot)
    • At least one widget listed as public for that bot: widget enabled, Standalone public checked, and the bot attached with the Assign action

    Where to find it

    StepURL
    Bots list (get username)https://app.addprocess.pro/addprocess/bots
    Public pagehttps://app.addprocess.pro/addprocess/web-chat/bots/public/{username} — also opened via the username link on the bots list

    In the app: Configuration → Create bot → Web Chat bot username link.

    Step-by-step workflow

    1. Create and activate a Web Chat bot.
    2. Create a widget; attach the bot; enable public/standalone options as needed; save.
    3. Copy the public page URL using the bot username, or click the username link from the bots list.
    4. Open the page as a visitor: confirm bot header and widget cards appear.
    5. Use Open chat on a widget card to land on {widgetDomain}/widget?widgetId=….
    6. Optionally still embed the same widget on a website for on-page chat.

    Configuration options

    • Bot username (from Web Chat bot credentials / metadata)
    • Widget public/standalone settings and allowed origins (origins matter mainly for embed; direct widget links use the widget domain)
    • Bot assignment behaviour for what happens after chat starts

    Expected result

    • Public URL loads the bot profile
    • Public widgets are listed with working open-chat links
    • Chat follows the activated assignment (menus, scenarios, AI, handoff)

    Limitations

    • Deprecated admin Web Chat bots list (/addprocess/web-chat/bots) is not the supported management UI—use Create bot + Widgets.
    • If the bot has no public widgets, the page shows an empty state rather than a chat.
    • Wrong username → not-found state.
    • This is not the Agent-role Chats inbox.
